# `cc-axi` command reference

Generated by `pnpm cc:gen` from `apps/cli/src/spec.ts`. Do not edit by hand. The design is
[07 §4](../../../docs/design/07-agent-friendly-design.md#4-cc-axi-the-axi-command-line).

Command Center - decisions, action items and meeting rhythm across your workstreams.

`cc-axi` with no arguments prints the home view. `-v`, `-V` and `--version` print the bare
version. Flags come after the command. Lists show 50 rows unless `--limit`
says otherwise. Output is TOON on stdout, errors included; exit codes are 0 (success or
`no-op`), 1 (an error) and 2 (a usage error: `E_USAGE`, `E_UNKNOWN_FLAG`).

Global flags, accepted by every command:

- `--format <toon|json>`: Output format; json is an escape for scripts (default: toon)
- `--principal <name>`: The agent principal to call as; its token is in run/tokens of the profile (default: cli-default, or $CC_PRINCIPAL)
- `--help`: the command's flags, defaults and examples

The local API is found through `<userData>`, read from `$CC_PROFILE_DIR`, or the app's default user data
directory; `$CC_PRINCIPAL` names the principal when `--principal` is not given.

## `cc-axi home`

The home view: today's meetings, attention counts and the most urgent items.

```text
cc-axi home
```

Local API: `home.get`.

Examples:

```text
cc-axi

cc-axi home --format json
```

## `cc-axi items list`

List action items.

```text
cc-axi items list [--workstream <slug>] [--owner <me|person>] [--state <lifecycle|active>] [--health <health>] [--due-before <YYYY-MM-DD>] [--fields <list>] [--limit <n>]
```

| Flag                          | Meaning                                                                         | Default |
| ----------------------------- | ------------------------------------------------------------------------------- | ------- |
| `--workstream <slug>`         | Only this workstream.                                                           |         |
| `--owner <me\|person>`        | Only items this person owns.                                                    |         |
| `--state <lifecycle\|active>` | Only this lifecycle state; active is every state but verified_done and dropped. | active  |
| `--health <health>`           | Only this health.                                                               |         |
| `--due-before <YYYY-MM-DD>`   | Only items due before this date.                                                |         |
| `--fields <list>`             | Extra columns, comma-separated: owner, health, carry, workstream.               |         |
| `--limit <n>`                 | Maximum number of rows.                                                         | 50      |

Local API: `items.list`.

Examples:

```text
cc-axi items list --workstream alderwick
cc-axi items list --owner me --due-before 2026-11-20
cc-axi items list --state claimed_done --fields owner,health
```

## `cc-axi items create`

Create an action item as a draft for the user to accept.

```text
cc-axi items create --workstream <slug> --title "<verb + deliverable>" --due <YYYY-MM-DD> --done-means "<text>" [--owner <person>] [--evidence "<requirement>"...] [--kind <todo|follow_up>] [--meeting <M-ref>]
```

| Flag                             | Meaning                                               | Default |
| -------------------------------- | ----------------------------------------------------- | ------- |
| `--workstream <slug>`            | Its workstream. Required.                             |         |
| `--title "<verb + deliverable>"` | Verb + deliverable, at most 120 characters. Required. |         |
| `--due <YYYY-MM-DD>`             | Due date. Required.                                   |         |
| `--done-means "<text>"`          | What a stranger could check. Required.                |         |
| `--owner <person>`               | Its one owner.                                        | me      |
| `--evidence "<requirement>"`     | An evidence requirement. Repeatable.                  |         |
| `--kind <todo\|follow_up>`       | Kind.                                                 | todo    |
| `--meeting <M-ref>`              | The meeting that captured it.                         |         |

Local API: `items.create`.

Examples:

```text
cc-axi items create --workstream alderwick --title "Send the signed SOW to the client" --due 2026-11-20 --done-means "The signed SOW is in the client folder"
cc-axi items create --workstream alderwick --title "Find out the renewal date" --due 2026-11-18 --done-means "The date is noted on the issue" --kind follow_up --evidence "A note with the date"
```

## `cc-axi decisions propose`

Propose a decision as a question with options; its decider decides in the app.

```text
cc-axi decisions propose --workstream <slug> --question "<q>" [--option "<text>"...] [--decider <person>] [--reversibility <two_way|one_way>] [--due-by <YYYY-MM-DD>]
```

| Flag                                 | Meaning                          | Default |
| ------------------------------------ | -------------------------------- | ------- |
| `--workstream <slug>`                | Its workstream. Required.        |         |
| `--question "<q>"`                   | Phrased as a question. Required. |         |
| `--option "<text>"`                  | An option. Repeatable.           |         |
| `--decider <person>`                 | The one person who decides.      | me      |
| `--reversibility <two_way\|one_way>` | How hard it is to undo.          | two_way |
| `--due-by <YYYY-MM-DD>`              | Decide by.                       |         |

Local API: `decisions.propose`.

Examples:

```text
cc-axi decisions propose --workstream alderwick --question "Do we offer phased pricing?" --option "Yes, in two phases" --option "No, one price"
cc-axi decisions propose --workstream alderwick --question "Which audit firm do we use?" --reversibility one_way --due-by 2026-11-30
```
