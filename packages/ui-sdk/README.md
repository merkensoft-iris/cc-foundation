# @cc/ui-sdk

The UI contract ([ADR 0008](../../docs/adr/0008-engine-owned-ui.md) decision 1): what any UI
that runs in Command Center's window builds on, the default UI and an engine's own alike. Import
it by its versioned entry point, `@cc/ui-sdk/v1` (ADR 0003 decision 2); there is no unversioned
root.

| Part               | Exports                                                                               |
| ------------------ | ------------------------------------------------------------------------------------- |
| `window.cc`        | `CcBridge`, `ShellInfo`, `Route`, `StartMode`, `RebuildState`, `CcError`, `isCcError` |
| Typed client       | `createClient`, `Client`, `Params<M>`, `Result<M>`, `UiMethod`, `UiMethods`           |
| API version        | `API_VERSION`, `apiVersionProblem(shell)`                                             |
| Routes and screens | `AppRoute`, `ScreenName`, `ItemsTab`, `SettingsSection`, `Ui`, `Screen<S, View>`      |
| Theme tokens       | `token(path)`, `TOKEN_PATHS`, `cssVariableName`                                       |
| Scopes             | `SCOPES`, `GRANT_ONLY_SCOPES`, `Scope`, `GrantOnlyScope`                              |

```ts
import { apiVersionProblem, createClient, token } from '@cc/ui-sdk/v1';

const shell = await window.cc.shell();
const problem = apiVersionProblem(shell); // a shell on another window.cc API version
const client = createClient(window.cc);
const home = await client.call('home.get', {}); // typed: Result<'home.get'>
element.style.color = token('color.accent'); // 'var(--cc-color-accent)'
```

## Generated, and stable within a version

`src/generated/methods.ts` is generated by `pnpm cc:gen` from the methods marked `ui` in
`packages/schemas/src/api/methods.ts`: each method's params and result are the types of its
zod definition, so no UI copies a result type by hand. A method whose params main fills in
before the core sees them (the backup folder) declares what the window sends as `uiParams`.

`contract/v<N>/` records, one file per method, the JSON Schemas of every `ui` method as the
window sends and reads it in extension API `N`. `pnpm cc:gen` (with or without `--check`)
fails when a method changes incompatibly within the version, and keeps the recorded contract:

- params keep accepting what they accepted (a field may become optional, an optional field
  may be added; nothing may be removed, become required or accept less);
- a result only gains optional fields (nothing may be removed or stop being always present,
  and no new value, type or field a UI must handle may appear);
- a method stays in the contract.

Anything else needs an extension API bump with its codemod (ADR 0003 decision 6). The rule is
in `scripts/ui-contract.ts`.

The package has no run-time dependencies: it imports `@cc/schemas` and `zod` as types only
(rule D3, enforced by ESLint), so a UI bundle carries none of the core's code. An engine's UI
imports it by entry point and `cc-build` bundles it (`packages/build/src/ui.ts`). The default UI
in `apps/desktop/src/renderer` is still served unbundled until it moves to `@cc/ui` (P1-26), so
it uses the contract's types and keeps its own copies of the few run-time pieces, checked
against these by its tests.
