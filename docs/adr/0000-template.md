- **Status:** proposed | accepted | rejected | superseded by NNNN
- **Date:** YYYY-MM-DD
- **Task:** build-plan task ID, for example P0-03, or none
- **Closes:** open question IDs this decision settles, for example OQ-08-05, or none
- **Spec:** design sections the decision rests on or changes, for example 02 §8.1

## Question

The question this record answers, in one or two sentences, as the build plan or spec poses it.

## Method

What was tried and how: environment (OS, versions), fixtures, prototype code, commands and
the measurements taken. Enough for someone else to repeat it.

## Result

What happened: measured numbers, pass or fail per fixture or criterion, surprises and
limits found.

## Decision

The choice made, stated so code and later records can cite it. Include the options not
chosen and why.

## Consequences

What changes because of the decision: design documents to update (and the PR that does it),
follow-up tasks, open questions closed or opened, risks accepted.

## Evidence

Links and paths that back the result: prototype branch or directory, logs, benchmark
output, screenshots, upstream documentation.
